# Plan: Tech Architecture Document Panel (Revised — Separate Agent)

## Key Design Decision

**TechScout stays untouched.** A new `TechArchitectureService` (dedicated Gemini 3 Pro agent) handles architecture analysis separately.

| Agent | Responsibility | Input | Output | Timeout |
|-------|---------------|-------|--------|---------|
| **TechScout** (existing) | Web research, tech recommendations, versions | Instructions string | `TechDossier` | 30s |
| **TechArchitectureService** (NEW) | Architecture mapping, feature analysis, data flows | `TechDossier` + `VisionDocument` | `TechArchitectureDocument` | 30s |

**Why separate?** TechScout already juggles query generation + 6 parallel web searches + synthesis. Adding architecture analysis risks context bloat, timeout pressure, and debugging complexity. Two focused agents > one overloaded agent.

---

## Data Flow

```
Planning Mode:
  User builds Vision Board (chat with AI)
    ↓ (auto-trigger: 3s debounce after name + 2+ features)

  1. POST /api/layout/tech-scout
     Input: serialized VisionDocument text
     Output: TechDossier → stored in useAppStore

  2. POST /api/layout/tech-architecture  (sequential, needs dossier)
     Input: TechDossier + VisionDocument
     Output: TechArchitectureDocument → stored in useAppStore

  UI: [Vision Board tab] | [Tech Architecture tab]
       (auto-switches to Architecture tab after generation)

Building Mode:
  [Start Building] clicked
    ↓
  POST /api/layout/pipeline with cached { techDossier, techArchitectureDocument }
    ↓
  Pipeline skips redundant TechScout call
  Enriches builder instructions with serialized dossier + architecture
```

## Step 2: Create Service — `src/services/TechArchitectureService.ts` (NEW)

Singleton service following the exact same pattern as `TechScoutService`:

- `TechArchitectureService` class with `analyze(dossier, vision)` method
- Uses `GEMINI_PRO_MODEL` from config (Gemini 3 Pro — **1M token context window**)
- `ARCHITECTURE_ANALYSIS_PROMPT` instructs Gemini to map features → tech, design layers, describe data flows, identify integration patterns
- Returns structured JSON parsed into `TechArchitectureDocument`
- 30s timeout, `_emptyDocument()` fallback
- `getTechArchitectureService()` singleton getter
- `serializeArchitectureForPrompt(doc)` exported serializer for Builder injection

### CRITICAL: Full Context, No Truncation

Gemini 3 Pro has a **1 million token context window**. The service MUST pass the **complete, unabridged** data:

**TechDossier** — serialize EVERYTHING:
- Every AI model recommendation with full `name`, `category`, `recommendation` text, `latestVersion`, `alternatives[]`, `confidence`
- Every framework recommendation with the same full detail
- All `emergingCapabilities` strings in full
- All `deprecationWarnings` strings in full
- All `sources` URLs

**VisionDocument** — serialize EVERYTHING, no summaries:
- `name`, `overview` (full multi-paragraph), `corePurpose` (full), `targetAudience` (full), `competitiveEdge` (full)
- Every feature with ALL fields: `id`, `title`, `userStory`, `description`, `behavior`, `acceptanceCriteria[]` (every item), `edgeCases`, `uxNotes`, `complexityLevel`
- `userFlow` (full narrative), `pageBreakdown` (full), `designSystem` (full)
- `marketAnalysis` if present

The serializers (`_serializeDossier`, `_serializeVision`) must NOT truncate, summarize, or limit character counts. The full context is essential for accurate architecture analysis — partial data leads to incomplete feature mapping and missed integration patterns.

**Prompt design**: Takes the full serialized TechDossier + full serialized VisionDocument → Gemini analyzes with complete context → produces comprehensive architecture JSON.

**Key**: Low temperature (0.3) for structured analytical output. `responseMimeType: 'application/json'` for reliable parsing.

### Modify pipeline logic (lines 52-91)
```typescript
const { files, currentCode, instructions, appContext, techDossier: cachedDossier, techArchitectureDocument } = body;

let enrichedInstructions = instructions || '';
let techDossier = cachedDossier;

// Skip TechScout if cached dossier provided from Planning Mode
if (!techDossier && enrichedInstructions.length > 0) {
  // No cache → run fresh (Building Mode without Planning)
  try {
    const scout = getTechScoutService();
    techDossier = await scout.scout(enrichedInstructions);
  } catch (error) {
    console.warn('[Pipeline API] Tech Scout failed (non-critical):', error);
  }
} else if (techDossier) {
  console.log('[Pipeline API] Using cached TechDossier from Planning Mode');
}

// Enrich with dossier
if (techDossier && (techDossier.aiModels.length > 0 || techDossier.frameworks.length > 0)) {
  enrichedInstructions = `${enrichedInstructions}\n\n${serializeDossierForPrompt(techDossier)}`;
}

// Enrich with architecture (if available from Planning Mode)
if (techArchitectureDocument) {
  console.log('[Pipeline API] Using cached TechArchitectureDocument from Planning Mode');
  enrichedInstructions = `${enrichedInstructions}\n\n${serializeArchitectureForPrompt(techArchitectureDocument)}`;
}
```

### Note on `serializeArchitectureForPrompt`
This serializer injects architecture context into the Builder's prompt. It should include **all** sections with full detail:
- Full system architecture overview + every layer with all technologies, responsibilities, connections
- Every feature mapping with full approach text and architecture notes
- Every data flow with all steps and technology labels
- Every integration pattern with full rationale and example
The Builder benefits from complete architecture context to produce accurate code.
